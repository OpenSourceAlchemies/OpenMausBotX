# OpenMausBotX — 让 AI 成为你的智能工作助手

**基于 OpenMausBot 开源项目的独立改造与扩展项目**

## 一、OpenMausBotX 是什么？

OpenMausBotX 是一款面向个人用户、开发者和团队的 AI 智能助手平台。

我们的目标很简单：

**让普通用户不需要掌握复杂的 AI 技术，也能使用人工智能帮助自己完成日常工作。**

现在，人工智能已经可以回答问题、编写文章、分析文件和生成代码。但是，真正让 AI 帮助我们操作电脑、使用软件、管理任务，往往还需要复杂的配置。

OpenMausBotX 希望改变这种情况。

我们以优秀的开源项目 OpenMausBot 为基础，围绕普通用户的实际需求开展二次开发，逐步完善 AI 模型接入、任务执行、电脑管理、工具扩展、费用管理等功能。

我们的方向不只是让 AI 回答问题，而是让 AI 逐步成为能够协助完成实际工作的智能助手。

## 二、OpenMausBotX 能帮助你做什么？

### 1. 与不同的 AI 模型对话

不同的 AI 模型有不同的特点。

有些擅长写作，有些擅长编程，有些适合分析复杂问题，有些价格更加实惠。

OpenMausBotX 正在建设统一的 AI 模型接入平台，希望让用户能够通过一个界面使用不同模型，而不必在多个网站之间来回切换。

规划支持三种使用方式：

- **平台提供的 AI 服务**：用户不需要自行购买多个模型接口，可以直接使用平台提供的模型服务。
- **使用自己的 AI 账号密钥**：已有模型 API Key 的用户，可以连接自己的服务商。
- **使用本地 AI 模型**：有条件的用户可以连接本机部署的 Ollama 等模型。

我们还计划提供智能模型选择功能，根据任务要求、模型能力和价格帮助用户选择合适的模型。

### 2. 让 AI 协助完成电脑任务

传统 AI 主要通过文字回答问题。

OpenMausBotX 则希望让 AI 能进一步参与实际操作，例如：

- 协助浏览网页和查找资料。
- 处理重复性的电脑操作。
- 使用授权的工具完成工作。
- 执行多个步骤组成的任务。
- 查看任务进度和执行结果。

例如，你可以向 AI 提出：

“帮我整理今天需要处理的工作。”

或者：

“帮我收集指定网站上的公开资料，并整理成表格。”

这些场景能否执行，取决于具体版本、已连接的工具以及用户授予的权限。

### 3. 连接更多工具和应用

OpenMausBotX 将 MCP（模型上下文协议）作为重要的扩展方向。

你可以把 MCP 理解成 AI 使用外部工具的连接器。

例如：

- 连接文件工具，让 AI 处理你允许访问的文件。
- 连接数据库工具，让 AI 查询指定的数据。
- 连接 GitHub，协助开发者处理代码相关任务。
- 连接业务软件，让 AI 参与工作流程。

未来，用户可以根据自己的需要接入不同工具，而不必依赖单一软件。

**安全提醒：** AI 只能在获得授权的范围内执行操作。涉及删除文件、修改数据库和执行重要任务时，应特别注意权限与确认设置。

### 4. 了解 AI 使用费用

使用 AI 服务时，费用往往是用户关心的问题。

不同模型的价格可能存在很大差异。如果不了解用量，长期使用可能产生意外支出。

OpenMausBotX 计划提供更加清晰的费用管理功能，让用户能够了解：

- 使用了哪个 AI 模型。
- 每次任务消耗了多少资源。
- 本次使用产生了多少费用。
- 一段时间内累计花费多少。
- 如何设置预算，避免超出预期。

我们的目标是让 AI 服务更加透明，让用户知道自己的钱花在了哪里。

具体计费方式以正式上线时公布的价格和服务条款为准。

## 三、普通用户怎样开始使用？

OpenMausBotX 的目标是让使用过程尽可能简单。

### 第一步：获取软件

通过项目正式发布的 GitHub 页面或官方网站获取适合自己设备的版本。

请尽量使用项目提供的正式下载渠道，不要随意运行来源不明的安装包。

### 第二步：启动工作台

OpenMausBotXWorkbench 是用户使用 AI 助手的主要工作界面。

工作台用于集中访问 AI、电脑管理和其他功能。

不同版本的菜单和界面可能有所区别。

### 第三步：连接 AI 服务

根据所使用版本的支持情况，可以选择平台提供的 AI 服务、自己的模型 API Key，或者本地部署的模型。

如果使用第三方模型服务，请留意对应服务商的收费规则。

### 第四步：向 AI 提出需求

使用自然语言告诉 AI 你需要完成什么工作。

例如：

“帮我写一份会议总结。”

“帮我分析这份文档的重点。”

“帮我规划一个软件开发任务。”

不需要学习复杂的命令，尽量把目标和要求说明清楚即可。

### 第五步：查看任务结果

如果任务涉及外部工具或电脑操作，应检查执行结果，并确认是否符合预期。

不要在未经检查的情况下，让 AI 自动执行重要的删除、付款或系统管理操作。

## 四、OpenMausBotX 与原始项目有什么区别？

OpenMausBot 是本项目的重要技术基础。

OpenMausBotX 在此基础上进行独立扩展，希望提供更适合普通用户的体验，同时建设自主服务平台。

主要改造和发展方向包括：

| 方向       | OpenMausBotX 的工作重点   |
| -------- | -------------------- |
| 自有服务平台   | 逐步迁移到自主 API 和服务管理体系  |
| AI 模型管理  | 统一连接不同模型供应商          |
| 智能选择模型   | 根据任务、能力和费用选择合适模型     |
| 电脑与任务管理  | 完善任务执行、设备管理和状态展示     |
| MCP 工具扩展 | 接入更多外部应用与业务系统        |
| 用量与费用管理  | 提供使用统计、费用明细和预算管理     |
| 多平台使用    | 完善桌面工作台、Web 入口和服务端部署 |

这些内容包括已经开展的改造和正在推进的开发目标，并不代表所有功能都已在当前公开版本中上线。

目前的工程资料记录了主要服务地址向自有 API 配置迁移的工作，但完整的自建云服务、计费链路和多端集成仍需要后续实现与验证。

我们会根据真实开发进度更新功能说明，避免把规划中的功能描述为已经可用。

## 五、我们的开发理念

OpenMausBotX 将继续围绕以下原则改进：

**简单易用**

尽量让普通用户通过自然语言使用 AI，而不必掌握复杂的配置技术。

**开放扩展**

通过标准接口连接更多模型、工具和应用，减少对单一服务商的依赖。

**费用透明**

让用户能够了解资源消耗和收费依据，逐步提供更好的预算控制方式。

**尊重用户选择**

让用户根据需要选择托管模型、自有模型密钥或本地模型，而不是强制采用一种方案。

**尊重开源**

遵守原项目和第三方组件的许可证，尊重原创作者、贡献者及其知识产权。
